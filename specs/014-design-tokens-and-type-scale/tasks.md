# Tasks: Design Tokens, Type Scale, and Spacing

**Input**: Design documents from `/specs/014-design-tokens-and-type-scale/`
**Prerequisites**: [plan.md](plan.md), [spec.md](spec.md), [research.md](research.md), [data-model.md](data-model.md), [contracts/design-tokens.md](contracts/design-tokens.md), [contracts/literal-scan.md](contracts/literal-scan.md), [quickstart.md](quickstart.md)

**Tests**: Included. The feature specification and contracts mandate specific automated tests (FR-018a, FR-018b, contracts T1–T11/A1–A9/C1–C7/U1–U6) that pin the token values and forbid regressions — these are not optional scaffolding, they are the feature's own acceptance mechanism (Constitution VIII).

**Organization**: Tasks are grouped by user story (US1–US5, spec.md priorities P1/P1/P2/P3/P2) so each story is independently testable. Because this feature's architecture is a single shared token/style module applied once per frame (FR-002), the module itself — including the US1 fix (`weak_text_color`) — is built once in Foundational; each user-story phase then applies the resulting roles at call sites and adds the story-specific verification.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: US1–US5, or omitted for Setup/Foundational/Polish
- Every task names an exact file path

## Path Conventions

Single Rust workspace at repository root. All new/changed files are under `crates/modplayer-ui/src/theme/`, `crates/modplayer-ui/src/**` (views/widgets), and `crates/modplayer-ui/tests/**`. `crates/modplayer/src/**` is scanned only, not edited.
