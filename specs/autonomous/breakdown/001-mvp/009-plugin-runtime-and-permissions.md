## Prompt

> Let small scripted plugins act on the music while it plays, without ever being able to take the player down. A plugin is a folder with a manifest (immutable reverse-domain identifier, name, version, supported API version range, author/license/source, entry script, required and optional permissions each with a one-line justification, declared network hosts, declared UI contributions, intended effect nodes) plus scripts and resources. In this slice the only source is "bundled": plugins shipped with the host, enabled by default with pre-approved permissions.
>
> Each plugin runs in its own isolated script context with no shared memory, its own scheduler and timers, and budgets: 4 ms CPU per event handler, 10% of one core averaged over a second, 64 MB memory, 10 MB storage. Exceeding a handler budget aborts that handler; exceeding the share or memory cap suspends the plugin. Plugin code never runs on the real-time path. On load the host hands the plugin a single API object shaped by its granted permissions; the plugin calls `ready()` before receiving events, and is suspended if it never does. Every request returns success or a structured refusal — `permission_denied`, `no_focus`, `invalid_state`, `not_found`, `rate_limited`, `budget_exceeded` — never a crash.
>
> Capabilities in this slice, each gated by its permission: observe playback (`track_changed`, `position` up to 60/s coalesced, `play_state_changed`, `queue_changed`), control transport and queue, read and write markers/loops/cues (own markers only), create and parameterize effect nodes (own nodes only, with a suggested chain position honored on insertion), receive meters, persist plugin-scoped and per-track key-value state (per-track state restored before `track_changed`), and timers including `schedule_at_position`. A plugin list shows name, version, source, enabled state, health (ok/warning/suspended), permission summary, and CPU/memory, with enable and disable.
>
> Disabling or suspending a plugin removes its UI, releases focus, disarms its loops, cancels timers, and orphans (does not remove) its effect nodes after an `unloading` event with bounded time to persist state. Uninstall is unavailable for bundled plugins.
>
> Acceptance: when a plugin enters an infinite loop in a handler, the host suspends it within its budget window, audio and transport continue uninterrupted, a non-blocking notice names the plugin, and the user sees Restart / Disable; three suspensions in a session auto-disable it. When a plugin calls a transport request without `transport.control`, it receives `permission_denied` and nothing else happens. When a plugin issues 1,000 seeks per second, excess calls return `rate_limited`. When a manifest requests a permission not in the catalog, the plugin is listed as "invalid manifest: <reason>" and not loaded.

## Scope boundary

Does not cover panels/overlays/shortcuts contributions, transport focus arbitration, registry or sideloaded sources, the permission approval sheet, network, files, clipboard, MIDI, or the custom buffer processor.
