# Data Model: Walking Skeleton

**Feature**: 001-walking-skeleton | **Date**: 2026-09-14

Types are grouped by owning crate. All numeric audio values are `f32` in the engine and `f64`/`u32` at the settings boundary. Value types that carry an invariant (ceiling, volume, preset) are newtypes whose constructors clamp; there is no way to hold an out-of-range value.

---

## 1. Value types (`modplayer-engine::types`)

| Type | Representation | Invariant / validation | Source |
|---|---|---|---|
| `SampleRate` | `u32` Hz | > 0 | FR-006 |
| `FrameCount` | `u32` | > 0 | FR-005 |
| `BufferPreset` | enum `Performance = 128`, `Balanced = 256`, `Safe = 1024` | exactly three variants; `requested_frames()`; default `Balanced` | FR-005 |
| `NegotiatedBuffer` | `{ preset: BufferPreset, frames: FrameCount, device_rate: SampleRate }` | `latency_ms() = frames / rate * 1000`; `duration()` = "one buffer duration" | FR-005, FR-013 |
| `CeilingDb` | `f32` dBFS | clamped to `[-6.0, -0.1]`, rounded to 0.1 step; default `-1.0`; `to_linear()` | FR-010 |
| `VolumePercent` | `u8` 0–100 | clamped; `to_linear() = v/100` (100 = unity); `to_db()` for display (`-inf` at 0) | FR-011 |
| `SafeVolume` | `{ enabled: bool, cap: VolumePercent }` | default `{ true, 50 }`; `apply(stored) = if enabled { min(stored, cap) } else { stored }` | FR-011 |
| `Transport` | enum `Stopped`, `Playing`, `Paused` | see state machine §5 | FR-015 |
| `DeviceId` | `String` (cpal `DeviceId` display form, or `name:<name>` fallback) | non-empty | FR-004 |
| `Theme` | enum `System`, `Light`, `Dark` | default `System` | FR-017 |

## 2. Audio Source (`modplayer-audio-source`, `modplayer-audio-source-synthetic`)

**`AudioSource` trait** — see `contracts/audio-source.md`. Fields of the synthetic implementation:

| Field | Type | Notes |
|---|---|---|
| `sample_rate` | `SampleRate` | default 44 100; constructor-configurable (tests) |
| `position` | `u64` frames | position within the looping track; wraps at `track_len` |
| `track_len` | `u64` frames | 22 s × rate (10 + 5 + 5 + 2) |
| `phase` | `f64` | oscillator phase, continuous across segment boundaries |

**Test track segments** (deterministic, computed from `position` only):

| # | Duration | Signal | Level | Purpose |
|---|---|---|---|---|
| 1 | 10 s | 440 Hz sine | −12 dBFS peak | phase continuity / dropout detection |
| 2 | 5 s | 1 kHz square | 0 dBFS | proves limiter engages |
| 3 | 5 s | sawtooth, linear sweep 100 Hz → 2 kHz | −12 dBFS | broadband check |
| 4 | 2 s | silence | — | loop seam visibility |

**Test tone**: 440 Hz sine, 1.0 s, 10 ms linear fade-in and fade-out, −20 dBFS peak (linear 0.1). Generated by the same crate as `TestTone { rate, elapsed_frames }`; `is_finished()` after `1.0 s × rate` frames.

## 3. Real-time engine (`modplayer-engine`)

### 3.1 `RtShared` (in `Arc`, atomics only — survives stream rebuilds)

| Field | Type | Writer | Reader | Meaning |
|---|---|---|---|---|
| `clock_frames` | `AtomicU64` | processor (once per buffer, `fetch_add`) | controller/UI | monotonic audio clock, source-rate frames consumed; never reset (FR-006) |
| `position_frames` | `AtomicU64` | processor (once per buffer) | controller (snapshot on rebuild), UI | transport position within the track; advances only while `Playing` |
| `peak_bits` | `AtomicU32` (`f32` bits) | processor (once per buffer) | UI meter | max `|sample|` at limiter output for the last buffer |
| `negotiated_frames` | `AtomicU32` | callback (first buffer) | UI label | frames actually delivered per callback |

### 3.2 `Processor` (owned by the stream callback; one per stream)

| Field | Type | Notes |
|---|---|---|
| `shared` | `Arc<RtShared>` | |
| `commands` | `rtrb::Consumer<Command>` | drained fully at the start of every `render` (buffer boundary) |
| `events` | `rtrb::Producer<Event>` | push never blocks; overflow drops the event |
| `source` | `SyntheticSource` | boxed only at construction |
| `transport` | `Transport` | |
| `master_gain` | `f32` linear | from `VolumePercent` |
| `ceiling_lin` | `f32` linear | from `CeilingDb` (clamped on the command side too) |
| `tone` | `Option<TestTone>` | |
| `output_stage` | `OutputStage` | resampler phase (`u64` 32.32 fixed point), `device_rate`, `device_channels`, preallocated `src_buf: Vec<f32>` (2 × 4096 + guard) |
| `scratch` | `Vec<f32>` | stereo mix buffer, preallocated for max frames |

**Render order per buffer** (fixed; no command can reorder or skip a stage):
`drain commands → source.fill(scratch) (or silence if not Playing) → × master_gain → + tone → limiter clamp → peak measure → output_stage (resample + channel map) → clock += consumed source frames`.

### 3.3 `ProcessorConfig` (constructor input; built by the controller from shadow state)

`{ source_rate, device_rate, device_channels, max_frames, transport, position_frames, master_volume: VolumePercent, ceiling: CeilingDb, shared: Arc<RtShared> }`

### 3.4 `Command` / `Event` — see `contracts/engine-commands.md`.

## 6. State machines

### 6.1 Transport (FR-015, FR-012)

```
Stopped --Play--> Playing --Pause--> Paused --Play--> Playing
Playing --Stop--> Stopped (position := 0)
Paused  --Stop--> Stopped (position := 0)
Playing --NoDeviceRemains--> Paused (position retained)      [FR-012]
App launch => Stopped, always                                 [FR-015]
```

### 6.2 Active output device (FR-004, FR-012, FR-014)

```
Launch:
  no confirmed device ─────────────────────────► DeviceCheck screen (system default preselected, tone auto-plays once)
  confirmed && present (id match, else name) ──► Active(preferred)
  confirmed && absent ─────────────────────────► Active(system default, is_fallback), Warning "device missing"
  zero devices ────────────────────────────────► NoDevice, Critical, transport disabled

Active(X) --DeviceLost(X)--> Active(system default, is_fallback) within one buffer duration, Critical "X lost", clock continues
Active(X) --DeviceLost(X), no default--> NoDevice, transport Paused, Critical
Active(fallback) --DeviceListChanged (X reappears)--> unchanged; Info "X available again"; preferred stays X
NoDevice --DeviceListChanged (any appears)--> Active(system default), Info, transport re-enabled
Active(X) --SampleRateChanged(X)--> rebuild stream (output stage only); clock and position preserved
Active(X) --user selects Y (Settings/DeviceCheck)--> Active(Y); preferred := Y only on "Yes"/Settings change
```

### 6.3 Device Check screen (FR-002–FR-004)

```
Open (first launch or Settings › Audio › Test output device)
  → tone plays once automatically (unless zero devices)
  select device | "Play test tone" | "No, try another" → tone restarts on selected device (<1 s)
  Yes         → persist {output_device, buffer_preset, device_confirmed = true}; close
  Skip for now→ device_confirmed stays false; close; screen returns next launch
```

### 6.4 Notification lifecycle (FR-016)

```
Raised → shown newest-first
  Info:     auto-dismiss at 10 s, or manual
  Warning:  manual dismiss only
  Critical: manual dismiss only
```

## 7. Relationships

```
modplayer (bin) ─► modplayer-ui ─► modplayer-core ─► modplayer-engine ─► modplayer-audio-source ◄─ modplayer-audio-source-synthetic
                                       │                  ▲
                                       └─► modplayer-audio-io ┘ (drives Processor::render)
```

`modplayer-engine` depends on `modplayer-audio-source` (trait) and `modplayer-audio-source-synthetic` (the only source this slice ships; the engine is constructed with the concrete `SyntheticSource`, so no trait object on the real-time path). No crate other than the future receiver's consumer path may depend on a streaming source (Principle IV).
