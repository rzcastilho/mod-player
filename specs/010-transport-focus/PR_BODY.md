## Summary

Replaces 009's placeholder single-holder CAS
(`request_focus()` → `invalid_state`/`focus_held`) with real
transport-focus arbitration (spec:
[010-transport-focus](specs/010-transport-focus/spec.md)): at any moment
the host or exactly one plugin holds transport focus; only the holder's
transport calls apply, everyone else gets `no_focus`; the user's own
commands always win. Three focus policies (manual, auto on interaction —
default, first request wins) are user-selectable and persisted. A new
Transport panel in Now Playing (`T` / header toggle) shows the holder,
every eligible plugin's request order, and one-click give/take back.
Plugin API bumped 1.0 → 1.1 (additive): `focus_granted{holder}` /
`focus_revoked{holder}` events.

## Constitution IX change request

> **Plugin API change request — 1.0 → 1.1 (010-transport-focus).**
> *What*: adds events `focus_granted{holder}` and `focus_revoked{holder}`
> (both `transport.control`); changes `transport.request_focus()` from
> "grant-or-`invalid_state`" to "always ok, grant reported by event";
> removes the never-standard `focus_held` reason string.
> *Why*: FR-3.3 / spec FR-003, FR-004, FR-014 — arbitration by user
> policy cannot be expressed as a synchronous return value.
> *Compatibility*: additive; every 1.0 manifest and script continues to
> load and run. A 1.0 script that treated `request_focus()`'s `true` as
> "I hold focus" now must wait for `focus_granted`; under the default
> policy it will receive `no_focus` on transport calls until the user
> gives it focus (documented in `docs/plugin-api/v1.md` §"Transport
> focus"). No deprecation window applies (nothing removed).
> *Docs*: `docs/plugin-api/v1.md` regenerated by `tests/api_reference.rs`.

(Verbatim from
[contracts/plugin-api-v1.1.md §4](specs/010-transport-focus/contracts/plugin-api-v1.1.md#4-written-change-request-goes-in-the-pr-body-constitution-ix).)
