# Contract: Plugin API 1.0 → 1.1 (transport focus)

**Crates**: `modplayer-capability-gateway` (`api/v1.toml`, `src/
{event,focus,refusal}.rs`, `tests/{gateway,api_reference}.rs`,
`docs/plugin-api/v1.md` regenerated), `modplayer-plugin-runtime`
(`src/bindings/{mod,transport}.rs`, `src/scheduler.rs`, `tests/
{bindings,scheduler}.rs`), fixtures `plugins/fixtures/{focus-a,
focus-b}` (+ `crates/modplayer-core/src/plugins/bundled.rs`).
Implements FR-003, FR-004, FR-010, FR-014; research R2, R6, R9.
Delta to 009's [contracts/plugin-api-v1.md](../../009-plugin-runtime-and-permissions/contracts/plugin-api-v1.md);
everything not listed here is unchanged.

## 1. Version

`api.version` → `{ major = 1, minor = 1 }`. Manifests declaring
`api = "1.0"` or `"1.1"` load; nothing is removed or renamed
(Constitution IX: minor = add only).

## 2. Requests (`api.transport.*`, `transport.control`)

| Call | Focus | Returns | Change vs 1.0 |
|---|---|---|---|
| `request_focus()` | – | `true` always (or `permission_denied` / `rate_limited` from admission) | **was** `invalid_state`/`focus_held` while another plugin held focus. Now: records the caller as a pending requester; whether/when focus is granted depends on the user's policy and is reported only by `focus_granted`. Calling it while holding focus or while already pending is a no-op success. |
| `release_focus()` | – | `true` always | now also withdraws a pending request (a plugin that asked but was not granted can un-ask). |
| `play/pause/toggle/seek/skip_next/skip_previous/arm_loop/disarm_loop` | ✔ | as 1.0; `no_focus` when the caller is not the holder | unchanged semantics; the host re-validates focus at application time as well as at admission. |

The reason string `focus_held` no longer exists. The refusal code set
is unchanged.

## 3. Events (new; delivered only to the plugin gaining or losing focus)

| Event | Requires | Payload | When |
|---|---|---|---|
| `focus_granted` | `transport.control` | `{ holder = "<your identifier>" }` | this plugin became the holder — by policy (first request wins), by the user's "Give focus", or by a first-request-wins refill |
| `focus_revoked` | `transport.control` | `{ holder = "host" \| "<other identifier>" }` | this plugin stopped being the holder — user "Take back"/"Give focus" to another plugin, a local host transport action under auto on interaction, its own `release_focus()`, or the first-request-wins track reset. **Not** delivered on disable/suspend/crash (the plugin is being torn down; `unloading` is what it receives, if anything). |

Ordering guarantees (FR-014), on the receiving plugin's own scheduler:
- plugin→plugin: the outgoing plugin's `focus_revoked` is enqueued
  before the incoming plugin's `focus_granted`;
- auto-policy host action: `focus_revoked` precedes the resulting
  `play_state_changed` / `loop_armed` / `loop_disarmed` / `position`.

Other plugins learn nothing (no broadcast). `ready_ack.capabilities`
is unchanged.

Handler registration is the usual `api.on("focus_granted", fn)` /
`api.on("focus_revoked", fn)`.

## 4. Written change request (goes in the PR body, Constitution IX)

> **Plugin API change request — 1.0 → 1.1 (010-transport-focus).**
> *What*: adds events `focus_granted{holder}` and `focus_revoked{holder}`
> (both `transport.control`); changes `transport.request_focus()` from
> "grant-or-`invalid_state`" to "always ok, grant reported by event";
> removes the never-standard `focus_held` reason string.
> *Why*: FR-3.3 / spec FR-003, FR-004, FR-014 — arbitration by user
> policy cannot be expressed as a synchronous return value.
> *Compatibility*: additive; every 1.0 manifest and script continues to
> load and run. A 1.0 script that treated `request_focus()`'s `true` as
> "I hold focus" now must wait for `focus_granted`; under the default
> policy it will receive `no_focus` on transport calls until the user
> gives it focus (documented in `docs/plugin-api/v1.md` §"Transport
> focus"). No deprecation window applies (nothing removed).
> *Docs*: `docs/plugin-api/v1.md` regenerated by `tests/api_reference.rs`.

## 5. Runtime rules

| # | Rule |
|---|---|
| RT-F1 | `bindings::dispatch` has no local arm for `TransportRequestFocus`/`TransportReleaseFocus`; both go through `rpc` (the exhaustive `match`'s `_` arm). |
| RT-F2 | `Gateway::admit` keeps checking `needs_focus` against `FocusToken::holder()`; the token is written only by core's `apply_focus_changes` (`set_holder`). |
| RT-F3 | `scheduler::event_to_lua` renders `holder` with `owner_to_string` (`"host"` or the identifier; never `"me"`). |
| RT-F4 | Direct-to-handle delivery bypasses `FanOut`'s permission filter, so `apply_focus_changes` itself sends only to plugins that hold `transport.control` (a plugin cannot be a holder or a requester without it — guaranteed by `TransportFocusView` filtering and by admission of `request_focus`). |

Named tests: `bindings::request_focus_is_rpc_not_local`,
`bindings::release_focus_is_rpc_not_local`,
`scheduler::focus_events_render_holder`, gateway
`admit_checks_focus_before_rate` (now using `set_holder`),
`api_reference::reference_is_current` (regenerated for 1.1),
`api_version_is_1_1`.
